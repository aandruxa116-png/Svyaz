# Этап 3: качество, история и совместимость

Работа продолжается в существующем основном веб-клиенте после этапа 2. Схема `users/handles/chats/messages`, Firebase config и правила не меняются. Экспериментальный сайт не используется вместо основного.

## Поведение веб-клиента

- Поиск существующих переписок: имя/название, @никнейм и видимое превью. Слова запроса учитываются вместе, регистр не важен. Старый E2EE-текст в поиск не попадает: индексируется только безопасная заглушка.
- Порядок чатов: активность с точностью Firestore Timestamp, затем ID для равного времени. Сообщения: createdAt + ID.
- Черновики раздельны по чатам, видны в списке и живут только в памяти страницы. Выход/смена UID, перезагрузка или закрытие страницы очищают их. После потери доступа к чату его черновик и очередь удаляются. Сессией Firebase Auth управляет SDK; это отдельно от хранения текстов.
- Отправка использует постоянный ID и транзакцию. «Сохранено» означает подтверждение сервера, а не доставку или прочтение. При ошибке остаются текст/ID и явная кнопка повтора; автоматической повторной отправки нет. Неотправленные сообщения отмечаются в списке чатов.
- История: последние 100 сообщений в реальном времени, более старые — страницами по 50 с сервера. Предыдущие загруженные строки сохраняются при движении live-окна. Прокрутка привязана к видимому сообщению; поздняя страница другого чата/UID игнорируется. Ошибка страницы не сбрасывает строки и курсор повтора.
- Настройки: тема, крупный текст сообщений, отправка Enter на компьютере. Shift+Enter всегда переносит строку, на мобильном отправляет кнопка. На диск приложение пишет предпочтения, но не тексты черновиков/историю.

## Поведение Android

Поиск по чатам учитывает имя/название, @ник и безопасное превью. Сортировка учитывает наносекунды и ID. Черновики раздельны по чатам, остаются в памяти ViewModel при переходах/фоне, очищаются при выходе, смене UID, завершении процесса или потере членства. Текст и постоянный ID неуспешной отправки доступны для ручного повтора; повторное нажатие во время запроса не запускает ещё одну транзакцию.

Подтверждённая история остаётся при сетевой ошибке в foreground; отказ в доступе очищает серверную историю. В фоне UI и подписки по-прежнему очищаются, после возврата нужен ответ сервера. Пагинация по 50, защита от поздней страницы другого чата, кнопка возврата к новым сообщениям. Настройка крупного текста сохраняет только предпочтение, а не сообщения.

## Автоматические проверки

`npm ci`, `npm test` в веб-репозитории. Android: Java 17 / SDK 36 / Gradle 8.13, `gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-daemon`. Браузерные проверки выполняются Playwright/Chromium с Auth/Firestore Emulator `demo-svyaz`. SDK в тестах направлен только на localhost, внешние запросы страницы блокируются. В публичном репозитории нет приватных Android-исходников и production-правил.

Новые регрессии: 165 сообщений без пропусков/дублей, сохранение scroll anchor при добавлении старой страницы, повтор страницы после offline, поздний ответ после переключения в другую группу, поиск по @нику/превью, черновик между вкладками, настройки Enter/размера текста и очистка полей редактора после выхода. Прежние тесты входа, групп, повторов и смены аккаунта сохраняются.

Приватный Android CI дополнительно запускает этот веб-клиент с точным `firestore.rules` из Android-репозитория и реальный Kotlin MessengerRepository вместе с веб-модулем. Результаты выполнения, APK и скриншоты — в CI соответствующего коммита; наличие теста не равно успешному прогону.

## Ручная матрица: два телефона и браузер

Автоматический прогон не заменяет физические телефоны. APK по умолчанию использует существующий Firebase; production deploy/замена правил для проверки не нужны и не выполняются. Владелец отдельно выбирает два тестовых аккаунта A/B и отдельную тестовую группу для ручных действий. Не удалять/переименовывать реальные профили, группы и историю. Для полностью изолированной ручной проверки нужна локальная конфигурация отдельного тестового Firebase-проекта на обеих платформах; её не публиковать на основном сайте.

1. Телефон 1: A, телефон 2: B, браузер: A. Проверить имя, @ник и одну и ту же переписку.
2. Написать Unicode/многострочный текст в браузере, затем с каждого телефона. Сверить автора, текст, порядок и историю после повторного входа. Повторное открытие личного чата не создаёт второй диалог.
3. Изменить тестовое имя/@ник в Android и затем в вебе. Другая платформа должна увидеть обновления, старый ник освобождён, занятый ник отклоняется.
4. Вводить разные черновики в двух чатах, переключать экраны и фон. В Android они сохраняются в памяти процесса; в вебе — в памяти страницы. После выхода/смены UID текст предыдущего аккаунта не появляется.
5. Отключить сеть во время чтения/отправки. Уже подтверждённые сообщения остаются; новое не считается сохранённым до подтверждения. Включить сеть, повторить вручную — одна запись, прежний ID, без перезаписи времени.
6. В тестовой переписке с длинной историей загрузить несколько страниц, прочитать старые строки, получить новое сообщение и проверить позицию прокрутки. Переключиться в другой чат во время загрузки страницы: чужие строки не появляются.
7. Проверить существующую группу, безопасную заглушку старого E2EE-сообщения и отсутствие сырого шифротекста в UI/поиске. Старые документы/ключи не менять.
8. Проверить настройки, крупный системный шрифт, клавиатуру и «Назад». Выйти из A и войти в B: пустые поля/черновики/очередь A, только доступные B чаты.

## Выпуск

Сначала ревью двух отдельных PR, затем решение владельца о merge/публикации. Android debug APK не заменяет выпуск с постоянной подписью; план подписи находится в приватном Android-репозитории (`docs/APK_SIGNING_PLAN.md`). Для обновления нужны совместимый сертификат, тот же applicationId и увеличенный versionCode. Секретные ключи не публикуются.

Счётчики непрочитанного не добавлены. Если они понадобятся, потребуется отдельно согласовать модель per-user read markers, права и поведение нескольких устройств; последняя активность чата не является признаком непрочитанного.
