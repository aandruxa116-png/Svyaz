# связь. — основной веб-мессенджер

Существующий сайт на GitHub Pages: index.html + app.js + data.js. Firebase Authentication и Firestore; обычные текстовые сообщения, без E2EE. Старые e2ee-сообщения показываются нейтральной надписью.

## Проверки этапа 1

Node 22, Java 21:

```sh
npm ci
npm test
npx playwright install --with-deps chromium
node_modules/.bin/firebase emulators:exec --only auth,firestore --project demo-svyaz --config firebase.test.json 'npm run test:browser'
```

8 регрессионных unit-тестов проверяют реальные функции data.js. Браузерные тесты выполняют исходный app.js в Chromium, подменяя только URLs SDK в тестовом HTTP-сервере на сборку того же Firebase SDK с жёстким подключением к demo-svyaz Emulator. Внешние запросы браузера блокируются. Тесты создают только синтетические аккаунты; production не используется.

`tests/emulator-only.rules` — упрощённая тестовая фикстура, **не предназначена для публикации** и не доказывает безопасность production. Совместимость браузерных операций с фактическими правилами проверяется отдельно в приватном Android CI: переменная FIRESTORE_RULES_PATH указывает на файл правил там. Android-код и приватные правила в этот репозиторий не копируются.

Никаких workflow публикации, merge или production deploy не добавлено. Проверки запускаются на pull request; существующие настройки GitHub Pages не меняются.

## Что исправлено

- Повторное открытие личного чата использует транзакцию без перезаписи владельца, истории, превью и timestamps; известные старые диалоги с произвольным ID используются повторно.
- Отправка имеет постоянный ID и атомарное превью. При ошибке текст остаётся в памяти с кнопкой повтора. Новое содержимое поля ввода не очищается запоздавшим ответом.
- Запросы и подписки привязаны к UID и поколению сессии. Выход очищает сообщения, профили, поля и очередь отправки.
- Профили и никнеймы обновляются в реальном времени; поиск проверяет актуальное соответствие handles/users. Onboarding не может переписать уже существующий профиль Android.
- Прокрутка не перескакивает вниз при чтении старых сообщений. Клавиатура и небольшой viewport не обрезают composer. В мобильном браузере системный «Назад» закрывает переписку.

Неотправленные сообщения и введённый текст хранятся только в памяти вкладки; выход и закрытие вкладки очищают их. Постоянные черновики и расширение истории относятся к следующему согласованному этапу.

## Ручная проверка

На двух устройствах/вкладках войти в существующие A/B, открыть один DM с обеих сторон, обменяться текстом с эмодзи/переносами, проверить группу. Отключить сеть, отправить, вернуть сеть, повторить: один документ без дублей. Проверить изменение имени/никнейма через Android и обновление веба; просмотр старых сообщений не должен прыгать к последнему. На телефоне открыть клавиатуру и вернуться кнопкой браузера. Выйти A и войти B: данные и ввод A отсутствуют. Реальные аккаунты и UI на физических устройствах автоматически не тестировались.

## Этап 2 — оформление и иконки

Общий знак «С» с репликой и голубой точкой связи, SVG/PNG favicon, Apple icon и 192/512px maskable icons. manifest.webmanifest использует относительные scope/start_url для существующего GitHub Pages пути; Service Worker и кэш пользовательских данных не добавлены, работа без сети не обещается.

brand.css согласован с Android SvyazTheme: тёмно-синяя основа, голубые акценты, круглые аватары с инициалами, формы, профиль и поиск. Светлая тема сохранена. Новый редактор профиля сохраняет имя и уникальный никнейм транзакционно в прежней схеме users/handles. Все кнопки вызывают реальные действия; загрузки фотографий нет.

13 unit/asset/contrast-сценариев проверяют основной код. В браузере дополнительно к прежним регрессиям проверяются редактор профиля, крупный шрифт, светлая тема и отсутствие сети. Design-тест снимает реальные страницы до/после на одинаковых синтетических аккаунтах в мобильном и настольном viewport. Baseline — неизменённый main этапа 1, зафиксированный в workflow; тестовый HTTP server меняет только SDK endpoints на Emulator. Скриншоты и отчёты — в артефакте web-stage2-screenshots-and-tests.

Для локального сравнения перед браузерными тестами подготовить baseline: `git worktree add --detach tests/.baseline 610dd8289921df58caa05c50670c4385a0be86c9`. Скрипт тестового server понимает /before/; production-сайт этот server не использует.

Production Firebase, rules и существующая публикация сайта не меняются. Этап 3 не начинается без отдельного подтверждения.
